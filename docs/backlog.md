## Platform and tooling

- ✅ **Starlette 0.37.2 → current (security, High)**, fixed in S1: FastAPI 0.111.0 → 0.163.1, Starlette 0.37.2 → 1.10.0 (pydantic 2.7.3 → 2.9.2, the minimum FastAPI 0.163 supports). `pip-audit` reports no advisory for Starlette, FastAPI or pydantic any more (it listed 7 for Starlette 0.37.2: GHSA-f96h-pmfr-66vw, GHSA-2c2j-9gv5-cj73, GHSA-86qp-5c8j-p5mr, GHSA-wqp7-x3pw-xc5r, GHSA-x746-7m8f-x49c, GHSA-jp82-jpqv-5vv3, GHSA-82w8-qh3p-5jfq). The upload endpoints (v1 and v2) now parse their body with explicit limits (`app.platform.uploads`: `MAX_FILES_PER_BATCH + 1` files, 10 other fields, 16 KiB per non-file field), and the `PendingDeprecationWarning` about `import multipart` is gone. v1 keeps parsing JSON sent without a Content-Type (`strict_content_type=False` on the root app only).
- **Other dependencies with advisories (security).** Found in S1 by `pip-audit` (`uv export --all-groups` of the lock): Pillow 10.3.0 (53 advisories, fixed in 13.0.0; a pdfplumber dependency, on the path that parses uploaded PDFs), pdfminer.six 20231228 (2), filelock, pyasn1, protobuf, tornado (flower), certifi, python-dotenv, and dev-only pytest and virtualenv. Upgrade in their own PRs, Pillow and pdfminer.six first (PDF parsing of untrusted files); **before E5**.
- **pydantic 2.9.2 → current.** S1 moved pydantic only as far as FastAPI 0.163 requires. Newer releases change JSON Schema output and some validation messages, so the upgrade re-records the v2 OpenAPI snapshot and regenerates the TypeScript client (E1-03).
- **sse-starlette 2.1.0.** Still works on Starlette 1.10 (the SSE snapshots pass), but it is old (3.x is current) and FastAPI 0.135+ has native Server-Sent Events. Decide between upgrading it and FastAPI's own SSE when the v2 stream changes next.
- **Node 20 → 22 or 24.** Node 20 is end of life. Upgrade `frontend/Dockerfile` (`node:20-alpine`) and the `frontend` CI job (`node-version: 20`) together. Best done at the start of E1, before the frontend rebuild.
- **Index on `resumes.campaign_id`.** The legacy foreign key had none either, so nothing regressed, but the campaign delete (`ingestion` deletes the campaign's resumes, E0-20), the campaign stats' resume counts and the resume list all filter on it. Add it in an expand migration when campaigns get large, or as soon as E2 adds `agency_id` (the index then becomes `(agency_id, campaign_id)`).
- **Remove `/api/v1` after E2.** The `/api/v1/candidates*` endpoints are a compatibility layer over Applications (spec §7) kept for the current frontend, and `legacy_candidate_map` exists only so old candidate ids keep resolving. Once E1's frontend runs on the new resource API and E2 has shipped, remove the legacy routes, their characterization snapshots and `legacy_candidate_map` (a contract migration, like E0-20).
- **Fake OCR returns placeholder text for tiny PDFs.** A PDF whose text layer yields ≤ 100 characters is treated as scanned (`ingestion.pdf`) and sent to the AI service's OCR. With `AI_PROVIDER=fake`, `FakeAIService.transcribe_page_images` returns a fixed placeholder ("Scanned resume (N page(s), digest …)"), so the profile has no name, email or skills and the resume fails as "not a resume". Real Gemini OCR handles such PDFs; only local smoke tests with very small PDFs are affected (found in E0-20's live check). Fix: make the fake OCR return a deterministic, resume-like text derived from the digest (a name, an email, a few vocabulary skills), so the fake pipeline completes, and update `test_scanned_pdf_falls_back_to_ocr_through_the_ai_service`. Workaround meanwhile: use a test PDF with more than 100 characters of text.
- **Frontend `npm audit` (security, Critical/High).** Found in E1-03, already on `master` (E1-03 adds none and drops `js-yaml`'s): `next` 16.2.9 (critical: middleware/proxy bypass with Turbopack, Server Actions DoS and SSRF; `postcss` and `sharp` advisories through it, fixed in 16.4.x), `axios` ≤ 1.19 (high, prototype pollution; only the legacy v1 client uses it and it goes with the old UI in E1-09), and dev-only tooling (`typescript-eslint`/`minimatch`, `shadcn`/`ts-morph`). Upgrade `next` and `eslint-config-next` together (read `node_modules/next/dist/docs/` for breaking changes), re-run lint, build and the contrast check. Before anything is exposed publicly (E5), and ideally during E1.
- **Request bodies with server defaults are required in the generated client.** `openapi-typescript` treats a property with a `default` as always present (right for responses: pydantic leaves defaulted fields out of `required`, but they are always sent), so `CampaignCreate.status` and `required_skills` are required in `POST /campaigns`'s TypeScript body (ADR 0006). Harmless (the form sends both) but surprising. Fix when it bites: list response fields with defaults as required in the v2 document (pydantic's `json_schema_serialization_defaults_required` on the v2 response models, with an OpenAPI snapshot update), then generate with `--default-non-nullable false`.
- **Branch protection on `master`** requires the five CI checks. The `backend-test` job now also runs the coverage gate (E0-21); no new check name, so nothing to change in the rule.
